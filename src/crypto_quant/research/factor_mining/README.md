# 因子挖掘：创意来源模块

入口为主命令 `crypto-quant factor-mine`，也可以运行 `python -m crypto_quant.research.factor_mining`。代码、研究记录和创意卡都在量化投资主项目内；MASFactorMiner仅作职责设计参考。

## 文件职责

| 文件 | 输入 → 输出 |
|---|---|
| `agent_ideator.py` | 研究任务与优化建议 → 因子候选、采用决定和定义校验 |
| `agent_calculator.py` | 候选公式与程序步骤 → 公式计算、程序错误修复和实际因子值 |
| `agent_evaluator.py` | 已保存的计算和评估证据 → 解释报告 |
| `agent_optimizer.py` | 全部A段候选证据 → 去向决定、修改任务和路线校验 |
| `contracts.py` | 显式研究选择、模型字段提取、候选、修改任务及配对合同 → 经校验的合同与定义 |
| `model.py` / `codex_model.py` / `mimo_model.py` / `model_config.py` | 模型契约、模型选择及各接口适配 |
| `runtime.py` / `structured_output.py` | LangChain运行层与模型回复结构校验 |
| `records.py` | 全部证据 → 实际模型上下文、按需原文读取、逐次请求档案和回复纠正 |
| `workflow.py` | 串联四个角色并负责A段循环、B段验证和创意卡交付 |
| `evaluation.py` | 公式值与独立标签 → 四类结果、配对修改检验、整批BH/BY校正 |
| `reporting.py` | 真实程序结果和单独模型解释 → Markdown报告、分组收益SVG图 |
| `cli.py` | 显式合同与逐小时币池 → 本地数据加载及上述流程 |
| `goal.py` | 用户目标、A研究历史与现有验收结果 → 优化Agent安排后续任务、持久化进度、等待恢复与完成核验 |
| `reoptimize.py` | 历史暂停候选 → 独立的优化复核记录 |

四个Agent是四种受限职责和提示词，通过同一模型接口调用。公式计算、统计、数据边界、配对判断和版本校验由程序执行。

## Goal模式（2026-09-17）

新增`goal-start`、`goal-status`和`goal-resume`入口。四个角色不变：优化Agent同时负责候选去向和整体研究任务；构想Agent生成具体候选及公式；程序保存状态、执行调度和验收。普通`explore`仍在空优化提案时结束；Goal收到该结果后继续选择新的研究方向，直到用户目标完成。

Goal文件必须显式提供`goal_id`、`objective`和`target_ideas`。目标文本及成果数量由用户在启动时指定，不设置默认成果数量、研究轮数、截止时间或总调用上限。当前成果类型为按既有B标准准入的因子创意卡：优化Agent在独立的成果核验上下文中判断其A段定义和证据是否符合目标文本，程序只计入真正获准入且有完整创意卡的匹配成果。自然语言匹配属于模型判断，程序核验的是准入证据和数量。

三条研究路线：

- **继续优化**：当前候选仍有获准修改提案，沿用四问、修改任务、构想生成公式和配对验证。
- **探索新方向**：候选Loop结束后，优化Agent读取完整A历史，安排下一项研究任务。每批使用独立运行目录。相同A面板上已经计算的相同展开公式和方向会标记重复，不重新送B；A数据改变后可带着新增依据重新研究。
- **等待数据**：优化Agent列出共享输入合同中的字段、A段最低有效观测数和依据。程序拒绝已经满足或超过固定币池容量的依赖；默认每60秒重读A检查，等待时不调用模型。满足后自动回到任务选择。不支持通过此入口自行扩展字段合同、研究区间或采集数据。

Goal的研究上下文只包含A记录。成果核验使用另一个记录目录，只提供已获程序准入的候选ID、A定义和A证据，不提供B数值或失败原因，也不把核验记录传回研究任务选择。B统计、门槛、工程样例排除、冻结及每批只读取一次的规则不变；C不读取。

状态保存为只追加的`events/event-*.json`：`active`、`waiting`、`paused`、`error`、`complete`。只有完成目标才正常结束；Ctrl+C保存暂停状态，`goal-resume`恢复原模型与输入设置。程序错误或耗尽现有单次重试会明确记为`error`并报错，不伪装完成。A恢复复用已接受的构想、计算、评估和优化记录，并直接核对A币池成员；B只有完整数值检查点时才能补解释，不能因中断重读B。运行锁防止同一Goal并发启动。

目录包含`goal.json`（目标、研究合同、输入路径、模型配置）、`events/`、`research_records/`、`completion_records/`、`model_calls/`及`runs/`。代码变更不会单独阻止Goal继续运行；研究合同和已保存证据仍须通过检查。操作示例见[因子挖掘Agent使用说明](../../../../docs/guides/因子挖掘Agent使用说明.md)的Goal章节。

## 候选决策与分流

优化角色先输出`decisions`，为本轮全部候选及此前继续优化的候选回答`research_basis`、`modification_hypothesis`、`verifiable_improvement`、`attempt_value`四个问题。各问题包含明确布尔判断和理由；研究现象由模型分析，不硬编码穷举。`evidence_refs`须引用现有记录，并至少包含当前候选的程序结果，保留／优化还须引用其评估记录。

`disposition`为`optimize`、`retain`、`pause`、`discard`。`continue_optimization`单独记录，因此`retain`可同时优化；暂停、淘汰禁止优化，暂停须写恢复条件。计算失败不能单独支持淘汰。所有决定均为模型研究判断，引用校验不等于理由已被证明。

只有四问均支持且提供完整修改任务与配对检验合同，才允许继续。第四问判断是否属于无新增信息的重复尝试、继续能否带来新的可验证信息，不判断剩余预算。Optimizer的proposal只包含原候选、精确证据引用、核心假设、已观察问题、修改假设、语义改动目标、固定部分及预先声明的配对判断规则；不包含新候选定义或最终公式。每条proposal必须对应本轮明确授权的已评估候选，并引用其评估记录。下一轮Ideator首次生成候选名称、完整公式、计算含义和版本关联；不能从未授权的父版本生成改进版。此前仍优化的原版会与本轮新版本一起重新判断；其他候选保留历史但不自动重启。无建议则自然结束循环。

最终状态写入`a-complete.json`的`candidate_decisions`和`retained_ids`，报告展示依据及恢复条件。冻结入口只接收`retain`候选，并将A决策随证据存入冻结批次及最终创意卡。B数值门槛和主项目交接边界保持原合同。

角色输出通过提示词中的JSON Schema明确字段、类型及必填项，程序继续严格检查，不将字符串布尔值自动转换。计算Agent必须返回并匹配当前`candidate_id`。这不是提供商原生约束解码的保证，返回结果仍可能被格式校验拒绝。

评估角色只提供`analysis`、`mechanism`、`conditions`、`falsifiers`、`limitations`、`next_steps`六项解释，不输出候选去向。四个角色统一通过`AgentGateway`接收，`model_fields`按声明的对象、数组、标量及可空字段递归提取；额外字段（含旧`decision`、Optimizer旧`candidate`、内层重复`read_records`）只留痕，不参与执行。必需字段缺失和类型错误仍报错；枚举、版本、证据及路线关系继续由程序校验。

外层`result/read_records`与原文读取请求也采用同一规则。每次`format_deviation`记录角色、额外字段JSON指针和原始回复位置，ID为`model-<call>-format`。原文保留在`model_calls`；后续记录与原文读取的继续消息只传提取后的字段，不重新发送附加字段的值。A／B报告展示全角色格式偏差。核心字段和研究判断不符进入下述回复纠正流程；研究合同、数据接口与冻结批次的直接一致性检查仍执行。

## 时间与数据合同

- 输入索引 `t` 是小时K线开盘标签，行内容至 `t+1h-1ms` 才可用。
- 首版标签 `perp_next_open_24h` 使用 `perp_open[t+25h] / perp_open[t+1h] - 1`。例如10:00那根K线结束后，以11:00至次日11:00的永续开盘价计算24小时收益。没有把下一根小时收益当24小时收益。
- A段每个已计算因子另存 `horizon_comparison`：复用同一因子值与方向，对照未来1h、4h、24h；标签为 `perp_open[t+1h+horizon] / perp_open[t+1h] - 1`。三列取所有期限共同有效的资产观察，统一按24h跨段边界排除，再计算Rank IC、各组收益、组间差、滚动及分阶段稳定性。报告并列展示，Evaluator和Optimizer可读取完整记录。
- 期限对照沿用合同的HAC带宽（小时采样时至少23阶），不假设1h收益独立；p值为未做跨期限校正的A段探索证据。收益未扣交易成本和资金费，较长期累计收益更大不代表预测更好。24h主评估保留原样，因此在共同样本减少时可能与对照的24h列不同。B冻结目标、批量检验和配对修改检验仍为24h；期限选择及独立验证合同另行确定。新运行生成对照，不改写旧运行记录。
- A/B/C边界为UTC整点、左闭右开。样本收益终点等于或超过下一段起点时排除；按小时评估时末尾25条小时观察被排除，因为标签还有下一小时开始的等待。报告保存实际排除小时数和资产观察数。
- A读取截止B前一小时，B读取截止C前一小时，C没有因子挖掘读取入口。预热记录只用于计算，不作为更早阶段的评估样本。
- 因子字段只来自共享35字段合同，标签独立存放。币池必须显式逐时给出，不从今天的30币名单反推历史。
- 整段都为false的资产不请求数据，返回明确的非成员状态和空值；曾在该面板内成为成员的资产保留入池前时序预热。A/B可以使用同一资产全集，尚未上市资产此前为false。
- 新冻结的B批次保存候选实际公式、含义、方向、统计规则及A证据，并单独保存完整的B成员资格文件。验证时直接核对B成员资格；B预热成员资格与已记录的A历史保持一致。旧批次仍可读取已有记录。

正式研究的日历日期、历史币池生成规则及既往数据使用审计仍需在合同中完成。代码支持执行该合同，不代替这些事实核查。

## 计算含义与修改范围

共享表达式编译器只按白名单、字段、参数和窗口检查公式，不推导单位，也不因量纲或跨币尺度拒绝公式。`add(spot_trades,1)`与原始价格的截面排名可以执行；构想 Agent 应说明比较的经济含义，实际预测能力由 A/B 统计检验判断。AST 节点及回看上限、数据可用时间和未来函数阻断继续执行。`expression_policy` 和 `count_literal` 已从新合同与算子目录移除。Calculator直接计算可执行公式；公式报错时依据程序错误尝试修复，并保留原始公式、修复过程和实际执行公式。候选的文字含义、金融假设和模型报告作为研究记录保存，不触发语义拦截。

优化任务先交回构想，逐条采用或放弃。Optimizer不提供候选或公式；Ideator采用时根据`modification_task.change_target`首次生成完整公式，并在`change_reason`说明如何落实修改目标及`fixed_components`。Ideator不得改写修改任务或配对判断标准；无法一致实现时放弃，由Optimizer另立新任务。相同假设下的任务可包含多个相互关联的语义改动，但不携带可执行表达式。程序仍执行表达式白名单、数据和时间边界、父版本与proposal关联及固定方向检查。

对照与新候选在相同时间网格、共同有效资产上重新排名和分组，计算配对改善及其不确定性。最低改善和允许IC损失在结果之前记录。上限仍达不到目标则停止，下限达到目标且满足损失限制则支持继续，无法区分则证据不足暂停。重启须关联旧路线并声明新增依据。完成轮数、候选数和路线尝试次数只作观察记录，不触发停止。假设与公式是否一致仍由Agent作研究判断，实际配对结果才检验修改是否帮助。

## 统计实现

- 横截面Rank IC使用平均并列排名。分组采用等宽排名分位区间、组内等权；相同因子值保持同组，缺组时不伪造收益差。
- 保留全部逐期、滚动和固定阶段结果，以及每个标的的有效样本概况。ICIR与组间差的均值/样本标准差均不年化。
- 均值置信区间及双侧检验采用Newey-West/Bartlett HAC、截距模型的小样本校正与渐近正态近似。lag由合同显式声明，至少覆盖重叠预测窗口；缺失期保留在原时间网格，不压缩间隔。常数或不足样本返回不可估计状态，不生成虚假的显著性。
- B批次所有候选的Rank IC检验构成统一FDR校正范围；有向组间差不参与FDR，仍按预定幅度门槛验收。无法估计的IC检验保留在范围内，原始p为null，校正时按1处理。BH/BY和目标水平由运行参数固定。
- B数值验证共同要求整批Rank IC校正支持与固定方向IC达到合同幅度。`admission_scheme`缺省为历史`baseline`：有向价差和阶段同向占比达到合同门槛、有效阶段≥2。历史`plan3`合同不含`plan3_tracks_gate`，仍须满足赔率轨（价差≥1.5 bp且阶段同向占比≥40%）、胜率轨（≥0.3 bp且≥60%）、均衡轨（≥1 bp且≥50%）任一。新合同设置`admission_scheme="plan3"`、`plan3_tracks_gate=false`及`fdr_method="BH"`后，三轨只作分类标签；准入由整批Rank IC校正、合同的有向IC下限和有向平均价差大于0决定。没有命中三轨的合格候选标为“基础型”，阶段结果仍完整记录。程序先记录`validation_result`，再让评估Agent解释；工程样例不能入池。旧运行合同、准入和创意卡含义不回写。
- 创意卡关联`a_research_decision`、`b_validation_status`及程序生成的`admission_evidence`。B数值通过与允许交付分别记录，完整策略验证状态仍为`not_started`。B未通过不会自动变成A段优化任务。
- A段的自适应搜索和修改比较始终标为开发证据。分组未来收益不是含成本策略净值。

统计方法参考：[HAC文档](https://www.statsmodels.org/stable/generated/statsmodels.stats.sandwich_covariance.cov_hac.html)、[多重检验文档](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html)。实现只使用现有NumPy/Pandas及标准库，不新增statsmodels依赖；HAC用独立的Bartlett矩阵计算作测试对照。

## 跨轮上下文与原文读取

每次请求读取全部A记录，包含定义、失败、修复、完整数值评估、模型报告、建议处置与实验决定。没有Top5、最近30条或固定200字符裁剪。请求的原始消息实际写入`model_calls/*-request.json`。

当前尚未绑定所选模型的专用分词器，使用UTF-8字节数作保守输入token上界；响应usage另行保留。用户已要求取消人为单次输出上限，当前示例合同`output_tokens=null`，请求省略`max_tokens`，由服务使用默认输出设置。此时本地`context_tokens`只用于输入上下文管理；合同明确指定输出数值时才预留对应容量。服务端自身的容量限制仍适用，省略参数不保证无限输出。输入上界不是供应商的精确token数，可能较早触发数值分页。

完整请求超预算时，相同字段覆盖统计作无损合并，长数值表替换成原文位置与总行数，模型可以用`read_records`请求任意记录的JSON指针和页码。定义、失败、修复依据、模型分析与决定保持原文。读取结果作为实际后续消息送入模型，所有请求均保留调用档案，不设总调用次数上限；上下文仍超容量则停止并保留证据，不继续静默删减。

B有独立记录目录，只开放评估角色，不反馈给A构想或优化。B访问开始前即留痕；一次验证中断也不会自动重跑B。

## 当前模型入口与历史Go记录

MiMo现通过LangChain `ChatOpenAI`与OpenAI SDK调用，SDK最多重试2次（含首次共3次），处理连接/读取中断、超时与可重试HTTP错误；耗尽后不再叠加AgentGateway网络重试。响应记录在同一次调用的`raw_response.responses`，保持原始推理内容、用量和错误脱敏；设置记录库版本与重试次数。输出结构仍由Pydantic和研究契约校验，解释文字不再触发语义拦截；不使用空报告替代失败。下方Go接口的5次重试规则只适用于历史Go实现。

当前所有在线入口通过 `model_config` 选择接口，默认小米 Token Plan 的 `mimo-v2.6-flash`，深度思考开启；本地 `.env` 配置 `MIMO_API_KEY`。MiMo 当前没有独立的思考强度档位，`enabled` 是此接口可用的最高设置。追加 `--provider codex` 使用保留的 `CodexModel`、`gpt-5.6-luna` / `max`。以下 SDK 说明仅适用于 Codex 接口。运行环境统一为根目录 `.venv` 中的 Python 3.12.13；依赖由 `uv.lock` 锁定。认证要求ChatGPT订阅；每次调用校验账号和模型，创建独立临时会话，关闭外部工具及继承的MCP/插件。完整消息作为带角色的JSON会话正文传入，首条system作为SDK的base instructions；没有消息截断或跨角色会话复用。额度、超时和认证失败停止，不改用其他供应商。SDK调用没有可指定的单次输出上限，只接受 `output_tokens=null`。

`model.py`中的Go适配器仅保留给历史契约测试，无生产CLI入口。以下Go鉴权和重试说明属于历史实现：

已适配直接Go API的chat/messages请求、服务要求的独立User-Agent和稳定`x-opencode-session`。密钥在运行时优先从指定环境变量读取，未设置时读取当前项目目录的`.env`同名项。支持单行裸值或成对引号，不做变量展开，不执行文件内容；空值、重复项和错误引号会报错，错误消息不回显密钥。密钥与请求头不写入证据。模型路由参考[Go官方文档](https://opencode.ai/docs/go/)；`responses`路由模型暂未适配，不应选用该路由的模型ID。

同一次API请求允许首次调用后最多重试5次（合计至多6次），由`AgentGateway`计数和留痕。可重试错误包括连接失败／超时、HTTP 408／429／5xx、服务响应JSON或结构损坏，以及正常／长度结束标志下的空正文。鉴权或参数等其他HTTP错误、内容过滤不自动重试；非空截断及模型正文JSON／角色格式／研究约束错误进入独立的回复纠正流程。模型、参数、消息、会话ID保持一致，重试前依次等待1／2／4／8／16秒。

每次尝试都生成独立`*-request.json`；重试请求记录`attempt`和`retry_of`。已取消总调用次数上限，合同不再包含`max_model_calls`。API失败的`*-error.json`记录是否重试、等待时间及停止原因；空正文也先保存`*-response.json`中的原始返回、结束标志和usage，再决定重试。网络错误只记录类型，响应中已知密钥脱敏，请求鉴权头不写入档案。

重试只重发当前API请求，不重跑已完成的构想、计算、评估或B数据加载。暂时性API错误耗尽重试后，计算核对失败记录到当前候选，解释失败记录为待补；构想／优化失败仍停止探索。不可重试错误明确停止，不自动切换模型。

## 回复纠正、候选隔离与报告补全

每次角色任务收到无效回复后，程序记录错误并继续请求纠正；无效JSON、必需字段／类型错误、错误证据引用及研究契约错误可纠正。解释文字不触发语义纠错。原文保存在`model_calls`；`invalid_model_response`记录错误与纠正序号。纠正消息提供原任务与错误原因，不把未接受回复中的附加字段重新发给模型。原文读取ID／路径／分页参数错误也能纠正；保存记录无法解析或内部程序错误不会作为模型格式问题吞掉。读取不以记录哈希不一致为阻断条件。

业务校验在提交状态前执行。无效构想或优化回复不会占用候选ID、建议ID或路线尝试次数。纠正与API重试不受总调用次数限制，不改变模型、研究合同或输出上限。超过纠正次数后，构想／优化任务停止；计算Agent记录`model_review_failed`并跳过当前候选，评估Agent记录`report_pending`，其他候选继续。上下文不足时，解释也记录待补。A段没有轮数、候选数量、单轮数量或路线尝试额度，只在优化角色返回空`proposals`时自然结束。

A段优化Agent可根据已完成数值和明确记录的解释缺口决策，但冻结入口要求所选保留候选已有合格解释。`a-complete.json.pending_report_ids`是探索结束时的快照；后续补全结果以命令返回及重新生成的`A-report.md`为准。原始记录和完成快照不覆盖。A报告只能在冻结B之前补全，不重开构想或优化。

B段先完成全部数值计算、批次校正与逐个程序判定，保存`b-numerical-complete.json`完成标记，再生成解释。补全时程序重新核对批次校正和准入决定，不使用记录哈希作为阻断条件。单份解释失败不会阻断其他解释，也不丢弃数值结果。返回`status=reports_pending`和缺失名单；只有全部解释就绪才生成最终`validation.json`。创意卡按各候选程序资格和解释完整性独立交付。

`factor-mine complete-reports --run-dir <运行目录> --stage A或B --model <Codex模型ID> --reasoning-effort max`仅补缺失解释。无需`--db`或`--universe`，不加载行情、不重算公式或统计；补全不受累计调用次数限制。B补全须有完整数值检查点，并核对合同、冻结候选、批次校正与程序准入决定。重复补全跳过已有解释，已有创意卡须与证据一致，不重复生成；仅可重建派生Markdown报告。

旧合同用于创建新运行时需移除`max_model_calls`字段，历史合同和失败记录保留供查阅。调用次数限制已取消，单个任务仍最多纠正3次、单次API请求仍最多重试5次。
