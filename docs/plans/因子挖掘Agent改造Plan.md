## 3. 已确认：保留构想 Agent，输出增加“公式含义”

构想 Agent 在现有输出中增加一段“公式含义”，明确这条公式具体计算什么，作为计算 Agent 核对和修复表达式的依据。

| 输出内容 | 职责 |
|---|---|
| 因子名称 | 标识候选因子 |
| 公式 | 使用可用字段、算子和参数构造的表达式 |
| 公式含义（新增） | 说明输入字段、窗口参数、计算顺序，以及涉及的时间和标的范围 |
| 金融逻辑 | 说明为什么这种关系可能有效，提出待检验的解释 |

公式含义应具体到能够据此还原计算步骤。例如，使用滚动窗口时要写清窗口长度、时间单位和是否包含当前期；使用截面计算时要写清比较范围。

### 输出示例

以下为说明输出格式的示例，尚未验证其预测能力。

| 输出内容 | 示例 |
|---|---|
| 因子名称 | `price_deviation_20` |
| 公式 | `sub(div(perp_close, ts_mean(perp_close, 20)), 1)` |
| 公式含义 | 对每个标的，使用截至当前时点、包含当前期的最近20根已收盘小时K线的永续收盘价计算均值；当前永续收盘价除以该均值，再减1。价格采用第13节统一的基础币单位口径。 |
| 金融逻辑 | 衡量价格偏离近期均值的程度，探索较大偏离是否对应后续反转。 |

“近期均值”“短期动量”等宽泛表述不足以单独作为修复依据。“公式含义”这一输出项的代码命名在实施时确定；可供公式使用的市场数据字段名按第13节执行。

## 4. 已确认：保留计算 Agent，核对公式含义并据此修复

计算 Agent 接收公式、原始公式含义、金融逻辑和可用字段／算子信息。每条候选在进入评估前都要完成含义一致性检查，覆盖首次生成、可以正常运行和修复后的公式。程序提供实际计算步骤，计算 Agent 核对其是否符合事先写明的含义。

```text
构想输出：名称、公式、公式含义、金融逻辑
        ↓
程序检查表达式并提取实际计算步骤
        ├─ 检查失败 → 计算 Agent 依据明确的原始含义修复
        └─ 检查通过 → 计算 Agent 核对原始含义与实际步骤
                       ├─ 一致 → 程序计算，成功后将因子值及对应定义交给评估
                       ├─ 不一致、原始含义明确 → 修正表达式并重新检查
                       └─ 定义不足或自相矛盾 → 退回构想 Agent 补充
```

程序检查或实际计算失败时，将错误信息交给计算 Agent；有明确含义依据才能修复，否则退回构想模块。每次修复后重新进行程序检查、含义核对和计算，全部通过后才能进入评估。

### 一致性检查方法

1. **程序提取实际计算步骤。** 从可解析的表达式及展开模板中提取所用市场、字段及单位、窗口长度和时间单位、计算顺序、是否包含当前已收盘期，以及截面比较范围。提取依据与实际执行共用第13节的字段和算子定义。
2. **计算 Agent 逐项对照原始含义。** 自然语言含义由模型理解，表达式中的字段、参数和计算步骤由程序提供。检查结果输出“一致、不一致、定义不足”，逐项保留原始含义、实际步骤及判断依据；不一致时指出具体差异。
3. **依据检查结果决定后续处理。** 一致且计算成功的候选进入评估；含义明确但表达式写错时，按原含义修复；含义缺失或自身矛盾时退回构想模块；改变原始定义形成新的候选版本。

检查依据是候选事先写明的计算含义，预测效果由后续评估判断，不能根据评估结果改写原始含义或据此认定修复正确。

### 修复边界

1. **以公式含义为准。** 可以修正表达式，使其准确表达已经写明的计算步骤。
2. **不自行补充研究选择。** 不擅自改变公式含义中确定的窗口、字段或计算方式。
3. **含义不完整或存在矛盾时退回构想模块。** 不通过猜测参数让表达式运行成功。
4. **改变因子含义时形成新的候选版本。** 保留原始定义和修改原因，不覆盖成“原公式修复成功”。

| 情况 | 处理方式 |
|---|---|
| 公式写成 `ts_mean(perp_close)`，含义明确写了20期永续收盘价均值 | 可依据含义补全为 `ts_mean(perp_close, 20)` |
| 公式可运行，但写成 `ts_mean(perp_close, 24)`，含义明确要求20期永续收盘价均值 | 标记窗口不一致，依据原始含义修复为 `ts_mean(perp_close, 20)` |
| 公式可运行，但写成 `ts_mean(spot_close, 20)`，含义明确要求20期永续收盘价均值 | 标记市场与字段不一致，依据原始含义修复为 `ts_mean(perp_close, 20)` |
| 公式缺少窗口，含义也只写“近期均值” | 退回构想 Agent 补充定义 |
| 主动改变原始含义，将明确的20期改为10期，或改用其他字段 | 作为新的候选版本处理 |

### 修复记录

保留原公式、原始公式含义、程序提取的实际计算步骤、检查结论及逐项依据；发生修复时，追加修复后公式、修改原因和重新检查结果，并关联计算错误及候选版本。后续评估使用的因子值应对应实际执行的公式，便于核对修复是否仍符合原意。

## 5. 已确认：因子评估的四类核心内容

评估目标是筛选在历史中反复出现、值得进入策略创意池继续研究的候选关系，并说明其适用条件及失效情况。当前指标方案面向横截面排序因子。

### 5.1 核心结果

| 评估内容 | 回答的问题 | 保留结果 |
|---|---|---|
| 预测关系：Rank IC | 因子排序与未来收益排序之间有什么方向和强度的关系？ | 各期 Rank IC、平均 Rank IC，以及对应预测期限 |
| 分组收益 | 因子从低到高，各组未来收益呈现什么规律、相差多少？ | 各组逐期及平均未来收益、高低组收益差、分组收益图 |
| 预测稳定性 | 关系能否跨期持续，何时衰减或反向？ | ICIR、滚动／分阶段 IC；组间收益差的均值、标准差、均值与标准差之比、方向一致比例及滚动／分阶段表现 |
| 统计可信性 | 对平均关系估计得有多精确，有多强的统计证据？ | 平均 IC、平均组间收益差的置信区间和显著性检验；样本数量、检验方法，以及第7节的批量校正结果 |

现有综合评分不纳入核心输出。因子的关系幅度、稳定性和统计证据分别展示；具体筛选门槛待定。这里的分组收益是指定期限的未来收益，成本后的完整策略表现交给后续策略验证。

### 5.2 稳定性的计算与展示

每个时点按当时的因子值重新分组，计算各组成员随后指定期限的平均收益。各组成员可以变化，分组规则保持一致。先得到逐期结果，再按预先确定的月份或阶段汇总。

- Rank IC 侧：保留逐期序列，计算未年化 ICIR，即 `平均 Rank IC / 各期 Rank IC 的样本标准差`；同时查看滚动及分阶段变化。
- 分组收益侧：保留各组逐期收益，重点观察高低组收益差。正向因子取 `高分组收益 - 低分组收益`；负向因子按固定的反向关系判断，保留原始高低组差及方向说明，不逐期翻转方向。
- 收益差的稳定性沿时间计算：均值、样本标准差、两者之比，以及符合固定预测方向的期数占比。分母是逐期收益差的时间标准差，不是同一期各组之间的标准差。
- 分阶段同时展示各组平均收益及组间差，观察优势是否仅由少数阶段贡献、收益差是否缩小，以及分组排列是否改变。

均值与标准差之比只描述稳定性的一个侧面。它不保留时间顺序，也不代替显著性检验；不设置脱离评估频率和期限的统一合格线。

### 5.3 统计可信性与 Agent 分工

程序负责计算指标、置信区间和检验结果。各期 IC 或收益差存在时间相关时，标准误须适应该相关结构，例如考虑 HAC；具体方法及参数在实施时确定。`标准差 / sqrt(期数)` 仅在相应独立同分布等条件下用于估计均值标准误，不直接用于存在重叠预测窗口的序列。

大模型接收完整评估结果，包括逐期／分阶段、分组、不同数据段及批量校正信息，解释预测方向、幅度、持续性、适用条件和证据强弱。报告覆盖支持、反对与证据不足的观察，不输出保留／淘汰等去向决定。A段四问及去向由优化Agent负责；B段程序按冻结规则判定验证和交付资格，评估Agent只解释。评估结果关联实际执行公式、公式含义及修复记录。

### 5.4 已确认：首期主要预测期限为未来24小时

2026-09-13核对加密货币研究后，用户确认首期统一使用未来24小时收益作为主要预测目标。

| 项目 | 已确认口径 |
|---|---|
| 输入数据粒度 | 保留第13节的1小时数据，构想 Agent 可以使用小时级价格、成交量、持仓等信息 |
| 主要预测期限 | 未来24小时；Rank IC、分组收益及相应稳定性和统计可信性结果均围绕同一期限计算 |
| 实际调仓频率 | 由后续完整策略设计确定，24小时预测期限不直接规定交易频率 |

例如，在UTC当天10:00得到因子值，检验其排序与当天10:00至次日10:00之间的币种收益排序是否对应。该示例说明预测时长；收益标签的具体价格取点和评估采样频率在实施前明确。

首期各候选在A、B段统一采用24小时主期限，并在搜索前固定。不能分别尝试多个期限后，只保留每个因子最好看的结果。若按小时形成连续的24小时预测，相邻收益窗口存在重叠，统计检验须按第5.3节处理时间相关，不能将其视为独立样本。

公开研究中，日频和周频均有代表性用法：[Liu、Tsyvinski、Wu的加密三因子研究](https://economics.yale.edu/sites/default/files/2022-10/LiuTsyvinskiWu2019%20COMMON%20RISK%20FACTORS.pdf)每周分组并观察随后一周收益；[Kakushadze的Cryptoasset Factor Models](https://arxiv.org/html/1811.07860)用此前价量信息研究下一天的开盘至收盘收益；[Babiak、Bianchi的JFQA研究（2025）](https://www.cambridge.org/core/journals/journal-of-financial-and-quantitative-analysis/article/mispricing-and-risk-compensation-in-cryptocurrency-returns/D8682A9FBA91A4869859423F74D7EA7A)研究日收益和周收益的可预测部分。本项目从这些已有依据的口径中选择24小时作为首期统一目标。

### 7.1 尝试记录与验证批次

1. A 段保留全部尝试，包括公式版本、窗口参数、预测期限、币种范围、使用区间及保留／淘汰原因。

4. 入池判断同时考虑关系幅度、预测稳定性和校正后的统计证据，并记录适用条件与失效情况。

### 7.2 FDR 与 BH/BY

已同意采用 FDR 控制方向并在实施后观察效果。FDR 控制的是：在适用条件成立时，整批检验中“错误拒绝原假设的数量／全部拒绝原假设的数量”这一比例的期望；没有拒绝时该比例记为0。

- BH 根据一批 p 值的排序和检验总数调整判断门槛，适用于独立或满足相应正依赖条件的检验。
- BY 可处理更一般的检验依赖关系，通常更严格。具体采用 BH 还是 BY，结合候选检验的依赖结构在实施时确定。
- 讨论中的 5% 是说明方法的示例；最终 FDR 目标水平尚未固定。
- FDR 校正调整统计判断，不修正样本偏差，也不表示每个入选因子具有某个固定的有效概率。

校正以单项检验的 p 值合理为前提，须先处理时间相关等问题。A 段的自适应搜索不能仅靠事后校正变成独立证据；A 段留痕、B 段固定批次验证和 C 段保留共同执行。

### 9.0 候选去向与四个研究问题

每个本轮候选，以及此前仍在继续优化的候选，都要得到一次明确决策。已保留且不再优化、暂停、淘汰的版本仍保留在历史上下文，但不自动重新进入决策队列。

| 问题 | 优化 Agent 的职责 |
|---|---|
| 有研究依据吗 | 从已有结果发现值得关注的现象，引用准确的程序记录，区分观察与推测 |
| 有具体修改假设吗 | 说明改什么、为什么可能改善 |
| 能验证是否改善吗 | 说明对照、预期变化与停止条件 |
| 还有尝试价值吗 | 判断是否属于无新增信息的重复失败尝试，继续能否带来新的可验证信息 |

研究依据由 Agent 分析，不预先穷举允许研究的现象。事先约定的是证据引用要求和数据边界；每次修改的对照与成功／停止条件必须在执行前确定。相同核心假设下可以联动指定多个相互关联的语义改动，不用窗口、平滑等类别或单一语法差异限制；最终表达式由构想Agent生成。程序核对记录存在、属于对应候选和输出一致性；这些检查不能代替研究理由的实质判断。

| 去向 | 输出要求及实际执行 |
|---|---|
| 继续优化（`optimize`） | 四个问题均获支持，并有完整修改检验建议；只将获准建议交给下一轮构想 |
| 保留待验证（`retain`） | 解释当前A证据为什么值得固定版本送B；必须已完成计算评估。可以同时继续优化，原版与新版本分别记录 |
| 暂停（`pause`） | 明确缺失证据或诊断，写明恢复条件；退出自动优化，不进入B冻结批次 |
| 淘汰（`discard`） | 说明充分的否定证据或无新增价值的重复；归档并退出自动优化，不进入B冻结批次 |

每条决定单独记录 `continue_optimization`，从而支持“保留原版，同时研究改进版”。暂停、淘汰不得同时要求继续。计算失败本身只能支持诊断暂停，不能直接判定无效。停止修改路线不自动淘汰原因子。

没有获准优化建议时，A循环自然结束。A段不再因轮数、候选数量或路线尝试次数耗尽而停止；完成轮数、候选数量及路线尝试次数只作观察记录。模型应根据证据选择继续、保留、暂停或淘汰。矛盾或不完整的模型回复由程序拒绝并保留停止记录，不自动改写研究决定。暂停后恢复需要根据新增条件另行作出研究决定，当前没有自动恢复入口。

冻结入口只接受最终明确保留的候选。A阶段保留仍是研究判断，不代表独立验证通过，B继续按原合同检查；正式研究门槛仍列在第11节。

### 9.1 继续研究的依据

下表是分析示例，不是限定 Agent 判断范围的穷举规则：

| 当前证据 | 处理方式 |
|---|---|
| 本地结果存在反复出现的预测关系，并暴露出具体弱点 | 优先开展有针对性的修改 |
| 相近加密市场的研究有依据，但本地尚未得到支持 | 先做范围有限的复现或诊断，注明原研究的市场、币种、频率和样本范围 |
| 只有单次高分、模糊故事，或“换个参数也许更好” | 暂不投入连续优化；说明缺少什么证据 |

结合第5节的完整评估结果，检查 Rank IC 与分组收益是否相互支持、关系能否在预先划定的阶段内重复观察、优势是否集中于少数币种或异常行情，并保留样本量与不确定性。不要求每个阶段都盈利，但应说明关系出现和失效的条件。

发现数据、时间对齐或公式含义问题时，先回到相应检查和修复环节；公式修复沿用第4节。外部研究中的历史表现只作为本地检验的线索，不能直接作为本地因子的有效结论。

### 9.2 修改前明确对照与预期结果

每条修改路线应在计算和评估前记录以下内容：

| 内容 | 要求 |
|---|---|
| 已有依据 | 关联原候选版本、具体评估结果及数据范围，区分已观察到的事实与外部研究线索 |
| 待检验问题 | 说明怀疑的具体缺陷，以及已有证据为何支持检查它；不能只写“提高 IC” |
| 本次改动与对照 | 优化Agent明确允许的语义改动目标、必须固定的其他部分，以及与哪个原候选比较；不写新候选定义或可执行公式 |
| 预期结果 | 写明若修改假设得到支持，应观察到什么变化；预先确定主要目标、最低改善要求或可接受的预测能力损失 |
| 停止与暂停条件 | 写明何种结果不支持这条路线，何种结果属于证据不足，以及需要补充什么信息 |

优化Agent单独写出原核心假设、已观察问题、修改假设、语义改动目标和固定部分。最终公式尚未生成，因此优化Agent不再回答`formula_alignment`。下一轮构想Agent在候选`change_reason`中说明实际公式如何落实任务，计算Agent再根据程序解析的实际步骤核对。程序检查字段、证据、父版本、proposal、固定方向和配对合同；文本完整不是假设已被验证的证明。

缺少具体依据、可检验问题或判断条件时，优化 Agent 先输出诊断需求，不为该路线生成修改任务。获准的修改任务及配对合同按第8.3节交回构想 Agent，由构想Agent首次生成完整候选后进入计算和评估。

### 9.3 根据实际结果继续、停止或暂停

程序计算对照结果及其不确定性；优化 Agent 依据修改前的预期和条件解释结果，不在看到结果后改写原来的成功标准。

| 结果 | 后续处理 |
|---|---|
| 预期变化出现，达到事先约定的目标，且没有触发停止条件 | 保留候选和证据，继续该研究路线或准备固定候选批次验证 |
| 在足以作出判断的证据下，预期变化未出现，或改善幅度达不到最低要求 | 停止该修改路线，保留原候选、实验结果及停止原因 |
| 估计范围仍同时容许明显改善和明显恶化，或缺少必要数据 | 暂停，标记证据不足，说明需要补充的数据或诊断 |

“不显著”不能单独作为已证明无效的结论。需要区分改善不足与估计不精确，例如合理估计的上限仍低于最低改善要求，可作为该次改进不足的证据。具体估计方法和判断阈值在实施前确定，沿用第5、7节对时间相关和多重尝试的处理原则。

停止一条修改路线不自动否定整个因子家族。重新启动应提供新增依据，例如新数据、发现的具体计算问题或不同的可检验解释，并关联此前失败记录。

### 9.4 加密货币场景下的检验示例

以下为检验设计示例，不代表本地已经观察到相应信号，也不冻结具体窗口、分层或阈值。

| 已有观察 | 待检验问题与改动 | 支持继续的结果 | 停止路线的结果 |
|---|---|---|---|
| 资金费率因子排序频繁变化，但预测信息仍能持续若干期 | 高频变化是否含可过滤的噪声；只调整平滑方式 | 排序变化减少，预测关系保留在约定范围内 | 平滑后信息消失，或预测能力损失超过可接受范围 |
| 动量在不同流动性组中的表现差异重复出现 | 流动性是否是适用条件；检验预先指定的分层或条件表达 | 条件关系在不同阶段及邻近分组规则下仍有支持 | 差异依赖精确切点、少数币种，且不足以重复支持该条件假设 |
| 新价量信号有效，但与已有因子相似 | 是否提供额外信息；比较加入前后的结果 | 在相同条件下达到最低增量改善要求 | 证据已足以判断增量改善不足 |

研究参考：[Presto 资金费率研究（2024）](https://www.prestolabs.io/research/can-funding-rate-predict-price-change)、[加密货币动量与流动性研究（2019）](https://arxiv.org/html/1904.00890v1)、[CTREND 研究（2025）](https://www.cambridge.org/core/journals/journal-of-financial-and-quantitative-analysis/article/trend-factor-for-the-cross-section-of-cryptocurrency-returns/4C1509ACBA33D5DCAF0AC24379148178)。这些材料提供诊断方向，本节决策规则是本项目的设计；Presto 展示的回测未计交易成本，也未展示完成降换手后的结果。

### 13.2 单位与加密货币专有字段的含义

- **先统一基础币单位。** 对第12.2节已登记的`1000PEPE`等对应关系，研究接口中的永续价格除以1000，基础币成交数量、主动买入数量和持仓数量乘以1000，USDT金额不变。其他已登记倍率同理；不凭名称中的数字猜测倍率。不同资产的“基础币单位”分别对应各自资产，不能直接把不同币的数量大小当作可比规模。
- **原始持仓量与统一字段分别命名。** 当前读取层的`open_interest`保留原市场单位；新增`open_interest_base`明确表示换算后的基础币数量。原始OHLCV和持仓记录保留，Agent接口提供明确的市场前缀及统一单位。
- **费率和比例使用小数。** `0.01`表示1%，多空比`2`表示多方是空方的两倍。资金费率、溢价指数、比例和USDT金额不随合约数量倍率缩放。
- **大户账户比和持仓比各自解释。** “大户”采用Binance按保证金余额划分的前20%用户口径；账户比比较净多、净空账户数量，持仓比比较相应持仓数量。`global_account_long_short_ratio`的范围是Binance该合约的整体账户。[Binance多空比定义](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Top-Long-Short-Account-Ratio)
- **资金费率保留结算周期。** 正费率表示多头向空头支付，负费率方向相反。`funding_rate`对应最近已知结算事件，不能将小时表中重复出现的同一期费率重复计为多次支付。[Binance资金费率说明](https://www.binance.com/en/academy/articles/what-are-funding-rates-in-crypto-markets)
- **累计费率以信号时点为截止。** `funding_24h_sum`和`funding_7d_sum`分别对截至当前的过去24小时、7天结算事件求和，每次事件只计一次；记录来源覆盖，不把未知缺失当作没有支付。它们不使用小时重复费率的滚动求和。
- **持仓与多空结构保留快照含义。** 小时表使用小时结束前最近的有效观测，不解释为整个小时的平均持仓或平均多空比；缺失与过期规则沿用第12.3节。
- **清算字段按覆盖情况开放。** 名义金额按既有源记录价格和数量口径重建，保留来源与计算口径；记录数不等于爆仓人数。来源不明、晚到及异常金额继续执行第12.4节的处理，字段仅代表该来源观察到的清算记录。

暂缓向公式开放`taker_long_short_volume_ratio`和其派生字段`taker_flow_net`：原始输入来自五分钟记录，第13.7节的跨年份抽样发现时间对齐关系不一致，尚不能为全部历史指定统一可用时间。不能直接将一条五分钟记录解释为整个小时的资金流。小时主动买入占比可由`spot_taker_buy_quote_volume / spot_quote_volume`或对应永续字段计算。

### 13.3 开放算子及其计算含义

以下`x`、`y`表示对齐后的字段或表达式结果，`n`是明确的正整数小时数；时序计算按单个币进行，截面计算按同一时点的研究币池进行。

| 算子 | 计算含义 |
|---|---|
| `add(x,y)`、`sub(x,y)`、`mul(x,y)`、`div(x,y)` | 加、减、乘、除 |
| `abs(x)`、`neg(x)`、`sign(x)` | 绝对值、取负、符号；符号输出−1、0或1 |
| `min(x,y)`、`max(x,y)` | 同一时点两个值的较小值／较大值 |
| `log(x)`、`sqrt(x)` | 自然对数、平方根 |
| `power(x,p)` | 幂运算；首版指数`p`使用明确的数字 |
| `ts_delay(x,n)` | 同一个币，准确往前n小时的值 |
| `ts_delta(x,n)` | 当前值减去n小时前的值 |
| `ts_return(x,n)` | 当前值／n小时前的值−1 |
| `ts_mean(x,n)`、`ts_sum(x,n)`、`ts_min(x,n)`、`ts_max(x,n)` | 同一个币最近n小时的均值、总和、最小值、最大值 |
| `ts_std(x,n)` | 最近n小时的总体标准差，`ddof=0` |
| `ts_corr(x,y,n)` | 最近n小时的Pearson相关系数 |
| `ts_cov(x,y,n)` | 最近n小时的总体协方差，`ddof=0` |
| `ts_rank(x,n)` | 当前值在该币最近n小时中的相对排名 |
| `cross_rank(x)` | 同一时点不同币之间的相对排名 |
| `cross_zscore(x)` | 同一时点跨币计算：当前值减截面均值，再除以截面总体标准差 |

`cross_pct(x)`作为`100 × cross_rank(x)`的别名，不增加另一套排名规则。因子算子的总体标准差口径适用于本节特征计算；第5节评估统计已明确的样本标准差口径继续保留。

### 13.4 所有算子共同遵守的规则

1. **窗口包含当前已结束的小时。** `ts_mean(x,24)`使用当前小时及前23小时；`ts_return(x,24)`比较当前与24小时前的两个值。K线行标签不代表当时已知完整K线，计算遵守数据可用时间，最早下一根K线执行。
2. **缺失记录不挤压时间。** 先维持连续的小时位置，缺一小时就保留空位；延迟、差分和变化率按准确的小时位置取值。滚动统计要求窗口内所需数据齐全，双序列统计要求成对数据齐全，不沿用参考项目“窗口齐一半就计算”的默认行为。
3. **异常计算结果为空。** 输入缺失、除零、对非正数取对数、对负数开平方，以及幂运算不产生有限实数等情况返回缺失值，不偷偷补零或截断。标准差作分母且为零时，相应标准化或相关计算为空；常数窗口本身的标准差可以为零。
4. **排名方向和并列规则一致。** 数值越大排名越高，并列取平均名次，随后按`(名次−1)/(有效数量−1)`映射到0—1；有效数量不足2时为空。`ts_rank`在完整时序窗口中执行，`cross_rank`在当时研究币池中对有效值执行，并记录实际参与数量；缺失值不获得名次。
5. **截面范围使用当时的研究币池。** 不将当前30币直接固定为全部历史样本，也不把同一资产的现货、永续别名重复计为两个标的。评估所需的最低有效样本数量继续按第11节确定。
6. **字段单位用于解释，不作公式准入。** 数据字段仍标注来源单位和币种倍率；当前公式编译器不推导单位，也不以单位相容或无量纲为通过条件。公式的经济含义由研究记录说明。

### 13.5 派生模板与构想上下文

基差、收益率、波动率等已有派生特征作为可展开查看的公式模板提供，展开后能追溯到具体字段、算子和参数，计算口径服从本节规则。例如：

```text
sub(div(perp_close, spot_close), 1)
```

该公式计算当小时永续价格相对现货价格的溢价比例；结果`0.002`表示溢价0.2%。模板说明计算含义，预测价值仍由后续评估判断。

构想 Agent 每轮上下文除第8节研究记录外，还包括：

- 字段名、中文含义、单位、原始频率、小时对齐方式、可用时间及缺失规则。
- 当前研究数据的字段覆盖率、缺失原因、质量状态和币种对应／倍率。

数据年龄与质量标记用于说明数据可用性，不加入本节因子公式的字段清单。未来收益标签仅供评估使用，不能进入因子公式；A/B/C数据使用边界继续执行第6、8节。

### 14.17 因子量纲标准化与输入/算子层重构规划（历史方案，后被方案 B 取代）

2026-09-27 确认：为解决当前静态 AST 量纲检查过于死板、容易误杀合理探索（如微小量纲偏置导致报错），同时保留对跨资产截面不可比和物理量荒谬混搭的防御能力，确定后续升级方向：**在输入和算子层面强制量纲标准化（无量纲化）**。

核心设计原则：
1. **输入层原子特征强制无量纲化（Dimensionless Inputs）**：
   - 基础行情数据在作为因子计算输入前，强制通过标准化或相对化算子消解绝对量纲：
     - 价格类通过 `ts_return` 或比率化（如 `div(perp_close, spot_close)`）转化为无量纲收益率或基差比率；
     - 成交量、持仓量、爆仓量等规模类指标，强制通过 `cross_zscore`（截面标准化）或 `cross_rank`（截面分位数，0~1）转化为无量纲相对强弱指标；
     - 资金费率、多空人数比等指标本身属于无量纲比例，直接参与计算。
   - 输入层全面无量纲化后，天然杜绝了“BTC 价格加 PEPE 成交量”的物理荒谬，且使得 30 个不同单价币种在截面上具备严密的经济学可比性。
2. **算子层精简与边界硬约束（Operator & Budget Guardrails）**：
   - 替代原先在 AST 编译期维护复杂的四维物理单位张量推导（USDT, base_asset, hour, count），将编译期算子校验收敛于纯数学运算与参数合法性；
   - 严格保留并强化抗过拟合的第一防线：
     - **AST 节点复杂度预算**：继续维持 `max_formula_nodes <= 80`（建议进一步探索收紧至 50~60），坚决阻断大模型生成深层循环套娃公式；
     - **时序回溯窗口限制**：继续维持 `max_lookback_hours <= 168`，防止内存膨胀与计算延迟；
     - **前瞻未来函数阻断**：严禁未来数据泄露。
3. **协同演进：B 段分类准入（多赛道自适应）**：
   - 输入层无量纲化生成的高质量紧凑公式，直接配合 B 段的“方案三（赔率轨、胜率轨、均衡轨）”自适应准入体系，形成从“前端输入纯净化”到“后端输出分流化”的完整量化研发闭环。
