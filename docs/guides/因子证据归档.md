# FM-v6 因子证据归档

每次研究运行保存过程记录，数值证据存入 SQLite。源码、合同示例和测试进入 Git；行情库、模型调用、运行结果和本地退役备份不进入 Git。

## 当前结构

```text
output_root/
  factor_archive_v2/
    registry.sqlite3
    factor-000001.sqlite3
  run_id/
    contract.json
    factor_archive.json
    a_records/
    b_records/
    frozen_batch.json
    b-access-started.json
    b-numerical-complete.json
    validation.json
    model_calls/
```

`FactorIdentity` 由展开公式、方向、表达式语义版本组成。注册表分配递增 factor ID；每份评估以 data_version、contract_version、evaluator_version、segment 和 horizon 定位，evaluation ID 与 value-set ID 同样为递增序号。相同自然键只允许相同证据，冲突不覆盖。

当前 data_version 采用 run ID 与段别，contract_version 保存完整 V6 合同，evaluator_version 为 `factor-eval-v1`。这些字段保持现有 V6 身份；运行之间不会仅凭相同公式复用不同数据的数值结果。

## 定位与读取

运行的 `factor_archive.json` 显式保存格式 `one-factor-one-file-v2` 和相对 archive_root。评估 JSON 保存 `data.factor_archive`，其中包含同一根路径、因子身份、评估键、evaluation ID 和 value-set ID。打开工件时按 marker 解析，代码快照和主源码使用相同规则。

评估指针必须与运行 marker 一致，身份与 ID 必须准确指向已存证据。移动一组运行和归档时保持相对关系即可；单独搬走运行目录会使其引用失效。新运行默认把归档写到 output_root 下，读取已有 V6 工件尊重其保存位置。

A 因子值按当前数据与计算语义压缩保存，支持分页。冻结批次引用确切 A 评估，Goal cycle 引用其当前运行记录，创意卡保留来源与程序决定。卡片不是自包含的全部数值证据，备份需同时保留运行目录、归档和对应创意卡。

## 保存边界

SHA-256 不参与因子身份、自然键去重或读取阻断。必要检查比较实际合同、公式、方向、成员资格、自然身份与递增 ID；SQLite 检查自身结构和内容。

当前矿工只创建与执行 V6 工件。旧 JSON/CSV 运行转换、旧 Goal 压缩和历史批量重验不属于当前主线；退役工具和原实验数据仅保留在本地，不自动迁移或重跑。
