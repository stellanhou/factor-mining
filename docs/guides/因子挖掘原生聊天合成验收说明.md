# 因子挖掘原生聊天合成验收

该配置只绑定三条既有本地测试聊天和一套确定性的六币合成数据。研究用途固定为 `engineering_check`；一次流程完成不等于因子达到 1 个合格目标，也不产生正式入池结论。

## 固定内容

- 项目 MCP 配置：`.codex/config.toml`
- 聊天、目标、合同摘要及输入路径绑定：`.codex/factor_research_synthetic_binding.json`
- 合成 run、SQLite 行情、成员资格文件和创意目录：`experiments/factor_mining/native_chats/synthetic_acceptance/`
- MCP role 在每个服务器进程的启动参数固定；工具参数不接收 role、chat ID、数据路径或 run root。
- 项目配置同时列出协调、A、B 三个服务器。项目级注册不能证明 Codex 将服务器限制给匹配的单条聊天；不得将此配置描述成聊天身份认证或聊天间不可读。

## 准备环境

在仓库根目录安装项目锁定的可选 MCP 依赖，并保留现有研究、图表和开发工具依赖：

```bash
uv sync --locked --extra dev --extra factor-mining --extra liquidation-data --extra native-chats
```

本固定绑定和合成输入由以下脚本一次生成。脚本会在固定路径已存在时失败，不覆盖已有运行：

```bash
.venv/bin/python scripts/prepare_native_chats_synthetic_acceptance.py
```

服务器从项目配置启动为官方 Python MCP SDK 的 STDIO 子进程。若服务未安装、绑定不完整、合同摘要不匹配或固定输入路径缺失，服务器会启动失败并报告具体错误。

## 角色与阶段

- 协调工具读取真实领域状态、构造 A 任务、核对 Goal 证据，并仅从已完成的 A manifest 引用冻结完整 retained 名单。
- A 工具只读取和写入开放的 A 证据；`a-complete.json` 写入后，程序拒绝后续 A 写动作。
- B 工具在存在已冻结清单后才可以验证。B 行情 loader 在 B 数值验证通过冻结前置检查并写入访问标记后才运行；数值检查点完成后只允许补交解释，不重读 B 行情。

项目设置或启动角色不能证明具体聊天调用者身份。当前验收按程序阶段门控报告，不承诺聊天间完全隔离。

## 验收记录

服务器进程启动和 MCP 工具调用需要分别检查。协议层测试使用官方 SDK 客户端；工具调用测试使用本目录固定合成数据。真实聊天中完成的 A、冻结、B 与 checkpoint 恢复记录由本次实施报告补充。工程样本的 B 准入和 Goal `objective_met` 按实际数值与凭据报告，不调整门槛。

## 当前实现状态（2026-10-15）

固定角色 MCP 服务现提供协调、A、B 三种静态工具表。A 通过带 `action_id` 的领域动作保存候选、计算/修复、解释、决定和完整 manifest；协调只能从该 manifest 冻结全部 retained 候选；B 在冻结后访问行情一次，保存数值检查点后只补解释与交付；协调的 Goal 核验只读固定 GoalSpec、A/B 证据和实际卡片。程序动作 receipt、stop/resume 与跨进程恢复在本地合成测试中验证。完整测试报告见[实施核验报告](../reports/因子挖掘原生三会话P2-P5实施核验_20261015.md)。

官方 MCP SDK 客户端到本地 STDIO 服务的合成 A→封存→冻结→B→交付→Goal 流程已经测试。原三个 Codex 聊天目前只做了 MCP 工具表、A 只读取证、协调任务准备和 B 冻结前拒绝的预检；没有在 App 聊天里完成完整 A/B 研究轮次。若修改了项目 MCP 配置，在 Codex 桌面端打开 **Settings → MCP servers → Restart** 后，应在原聊天中检查 `/mcp` 并重复这些只读预检；不要创建替代聊天。

项目配置注册的三个服务器不证明调用者聊天身份，无法阻止一个聊天读取另一个聊天的消息。程序保证新运行的 A 完成 manifest 后不再允许 A 写入，B 行情不会在冻结前加载；这些阶段限制不能描述为跨聊天保密。程序 stop 会拒绝新动作并等待当前安全提交结束；原生模型生成是否已停止由宿主负责，本工具返回 `model_status=unknown`，需要宿主读取原聊天状态才能报告。P0 的严格聊天隔离、App 端完整研究与恢复、长上下文恢复仍未验收。

以上合成验证只使用固定六资产工程样本，不使用真实行情或正式 B；工程模式下卡片不会被计入研究目标，流程完成不等于 `objective_met`。
