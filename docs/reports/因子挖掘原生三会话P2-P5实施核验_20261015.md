# 因子挖掘原生三会话 P2-P5 实施核验

日期：2026-10-15。此报告记录本地程序服务和合成验收，不代表真实行情研究或原生 App 三聊天完整联调已经完成。

## 实施范围

- **P2 A 动作：** `ResearchActions` 提供静态角色工具表、A 证据检索与分页、实验预声明/收尾、候选计算/修复、解释与决定，以及完整候选与语义匹配 manifest。manifest 写入后，A 证据封存。A 记录引用和 GoalSpec 均由固定服务绑定校验。
- **P3 MCP 接入：** 新增官方 Python MCP SDK 的 STDIO 服务和固定 run/输入/Goal/聊天绑定。coordinator、A、B 通过独立静态 allowlist 获得工具；工具参数不提供角色、聊天 ID、任意文件路径或 run root。
- **P4 B 与总目标：** 协调从完整 A manifest 冻结全部 retained 候选；B loader 在冻结后、访问标记落盘后才调用一次。纯数值检查点读取会核对冻结名单、成员、归档评价与 D、BH 家族和准入；检查点完成后可保存解释、卡片与 B 交付清单，不会重新加载行情。Goal helper 重新核验数量/质量目标、语义匹配、程序准入、真实卡片内容与 hash。
- **P5 停止与恢复：** run 级跨进程互斥、动作 ID 参数摘要、开始/完成收据、停止/恢复事件及动作边界 commit。A seal 和 B freeze 在同一 run 锁下、写入自身 started 收据前拒绝尚未对账的 A 动作；原动作可按其固定 ID 从已保存证据恢复回执。A seal 后的已完成候选只允许只读恢复，不会重开 A 写入。测试覆盖候选定义写入后、值集归档后、数值检查点后、停止计算中、恢复提交、B 已访问但未完成及冻结后写入拒绝。存在值集归档时从原归档恢复，不重算；归档前没有数值提交时，以同一动作 ID 继续该未完成动作。

旧无 manifest 运行保留已有读取/恢复契约。新 action-bound run 不可通过旧 A resume/report、B validate/report 入口绕过动作 ID。报告修订按追加记录中的 revision 序号选择最新版本；B 完成交付后冻结对应解释与卡片凭据。

## 验证

新增独立进程恢复用例前，首轮定向组合使用六资产合成数据、FailingModel 和官方 SDK 客户端：

```text
.venv/bin/python -m pytest -q \
  tests/test_factor_native_recovery.py \
  tests/test_factor_native_goal_evidence.py \
  tests/test_factor_numerical_checkpoint.py \
  tests/test_factor_native_chats.py \
  tests/test_factor_research_actions.py

26 passed, 2 subtests passed, 22.74 seconds
```

测试覆盖 action ID 参数冲突、归档前后恢复、stop/ack/resume、Goal 数量与质量证据、篡改检查点/归档/卡片、B 不重读、旧流程回归，以及官方 SDK Client→本地 MCP 服务的合成 A→seal→freeze→B→delivery→Goal 链路。完整项目测试套件运行结果为 **341 passed、254 subtests passed、14 warnings，132.61 秒**。随后新增的 `test_native_mcp_stdio_checkpoint_recovery_in_fresh_b_process` 单测单独通过（1 passed）。本轮缺陷修复后，封存前待回执恢复与封存后只读回执恢复两个新用例加入 `tests/test_factor_native_action_contracts.py`；四个受影响定向测试文件合计 **23 passed、14 warnings，18.11 秒**。所有执行与单独用例合并覆盖 **344 个唯一测试**，不是一次 344 项全量运行。警告来自 Matplotlib/Pyparsing 的弃用提示，不影响测试结果。此前 P1 核心提取的固定数值对照按 2026-10-13 的 [P1 核验报告](因子挖掘原生三会话P1实施核验_20261013.md)记录。

## 尚未验收的宿主能力

这次 SDK 客户端到本地 MCP STDIO 服务的端到端测试不是 Codex App 原生聊天端研究。三个既有聊天的工具与只读状态预检已记录于[原生聊天预检证据](../../experiments/architecture_comparison/native_p2_p5_acceptance_20261015/native_chat_preflight.json)；其依据是 `read_thread` 摘要及工具调用状态，不是原始 MCP 响应或完整 A 研究。服务进程可能仍运行旧代码，源码和配置变更不证明其进程内存已刷新。修改完成后，应在 Codex 桌面端 **Settings → MCP servers → Restart**，在原聊天中用 `/mcp` 核对并重新执行只读预检，再继续有界合成 A/B 联调；无需创建替代聊天。

当前项目级 MCP 配置不能作为聊天身份认证。程序限制了各角色可调用的领域工具以及 A/B 程序记录范围，但不能证明 A 聊天无法读取 B 聊天消息。宿主是否停止原生模型生成也未能从领域服务观测，状态继续返回 `unknown`；程序 stop 只负责拒绝新程序动作并等待安全提交。P0 严格跨聊天隔离、App 中完整 A/B 研究轮次、长上下文恢复及原生模型停止均未标记完成。

所有本轮测试使用固定合成行情；未读取真实行情、未访问正式 B、未进行模型因子研究、未进行架构对照实验。工程模式通过流程也不构成因子有效性或真实目标达成证据。P6 实验采用结论尚未开始。
