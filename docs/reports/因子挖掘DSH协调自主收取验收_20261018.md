# DSH 协调自主等待与收取 A 结果验收

日期：2026-10-18（北京时间）。DSH 固定版本 `0.2.1-rc.2`。

**本阶段工程目标通过；研究目标仍 incomplete。** 一条人类启动指令之后，协调派发 A 并结束自己的回合，A 结束后由宿主通知自动唤起。协调独立读取 A 完整决定、报告和原始评估摘要，完成零保留结项、核验领域 Goal 并暂停原 native Goal；操作者没有粘贴 A 结果或发送“继续”。自主结项之后另做了一次纯进度追问，协调引用已有证据回答，未恢复或派发。

## 实现

- 协调新增 `read_a_result(candidate_id)`：返回当前运行该候选的定义、最新完整决定、报告、记录 ID、精确指针和记录 hash，最大 32 KiB。决定尚未形成时明确为 null；封存与未封存分开表达。
- 协调新增有界 `read_a_evidence`：复用现有 A 记录白名单、来源验证与 JSON pointer 读取，最大 16 KiB。大对象不返回正文，要求缩小到精确来源指针；不开放文件路径、其他运行或 B/C 记录。
- 进度概要补上 A pending action 与已封存 manifest 引用，避免协调把 A 待提交动作说成空闲。
- Host 监听固定 A Session 的公开 `session/event`。收到 `turn/end` 后先等待原生 `Agent.whenIdle()`，再校验接受回执、固定工单与实际入队原文，向协调的原 Session 投递一个固定结果通知。协调等待期间不占住模型回合，不靠模型反复查状态。
- 结果通知不把回合结束当作任务或研究完成。协调根据获准证据决定既有 continuation/recovery，或零保留结项。回合错误按阻碍处理，不自动重试；若领域封存已完成，仍准确核验既有交付。
- durable 通知回执处理重复/旧事件；暂停、Stop 与卸载使等待中的通知失效。暂停或 disarmed 的 Goal 阻止后续派发。Stop 若清掉已接受但未入协调历史的通知，只有人类显式恢复后才可用同一原生 request ID 补收，不重发 A 工单。原生 prompt 自身检查 inbox 和历史来去重。

未增加研究模型调度器、Python 选题循环、新前端框架或无界重试。

## 限制与实际失败

- A 在封存后的下一次模型请求触及每轮 8 次上限，因此该回合记录为 error。协调核对出 A 已封存、完整决定已保存，未重试、重算或重派，随后准确结项。没有提高预算。
- 协调首次创建 Goal 使用了不匹配的 objective，被拒绝；从绑定原文改正后只创建了一个合法 Goal。
- 协调首次读取整份评估触及 16 KiB 边界（372471 字节），没有返回大正文；随后读取 `/summary` 成功。这验证了窄读约束，没有放宽输出门槛。
- 真实进度追问发生在自主结项之后。A 仍运行时不占用协调回合，以及 pending 决定/动作的读取由定向检查覆盖；没有把它写成一次真实的运行中 UI 追问验收。
